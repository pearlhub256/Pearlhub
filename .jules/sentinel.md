## 2024-08-05 - Hardcoded API Key Exposure in Vite Config
**Vulnerability:** The `vite.config.ts` file was using the `define` property to expose the `GEMINI_API_KEY` from environment variables directly into the client-side bundle. This makes the secret key publicly accessible in the browser.
**Learning:** This is a critical security flaw. The `define` feature in Vite is a direct replacement, meaning it will replace any instance of the key in the code with the value. Even though the key was not actively used in the application's source code, its presence in the build artifact poses a significant risk if discovered. This highlights a critical vulnerability pattern to watch for in this repository's Vite configuration.
**Prevention:** Never use Vite's `define` property to inject secrets. For client-side variables, they should be prefixed with `VITE_` and accessed via `import.meta.env.VITE_...`. For secrets, they should only be accessed server-side and never exposed to the client. I will audit `vite.config.ts` for similar issues in the future.
